# 亚马逊选品 · 两层框架 RAG Demo

**在线体验**：https://wynn-lim.github.io/amazon-market-rag/ （手机可直接打开）

---

## 一句话

把「先看市场有没有肉吃，再看缝隙在哪」这套选品经验，做成了一个**填数字就能出结论、还能追问依据**的工具。

## 解决什么问题

选品最怕两件事：**拍脑袋**和**对不上账**。

- 经验都在脑子里，换个人、换个类目就重来一遍
- 卖家精灵的数字摆在一屏，看不出该看哪几个、看到什么程度算过关

这个 demo 把 12 个指标的分层评分做成规则，填进去就知道这个类目**该进、该绕、还是得带条件进**；每个结论都能点开看依据出自框架哪一条。

## 三个页签

| 页签 | 做什么 |
|---|---|
| **市场体检** | 填 14 个指标 → 两层分别打分、命中否决线直接标红、每条附「依据」和「下一步动作」 |
| **知识问答** | 问「点击集中度多高算危险」，答案带 `[S#]` 引用编号，能回溯到原文 |
| **检索试玩** | 直接看提问命中了知识库哪些片段、各得多少分——检索质量看得见 |

## 两层框架怎么落成规则

**第一层 · 市场容量与需求** —— 确认「有肉吃」

| 指标 | 健康线 |
|---|---|
| 核心词月搜索量 | ≥ 10,000 |
| 核心词月增长率 | > 10% |
| TOP100 月均销量 | 600—3,000 |
| 新品进榜数量与占比 | ≥ 5 个且 ≥ 10% |

**第二层 · 竞争格局** —— 判断「缝隙在哪」

| 指标 | 健康线 |
|---|---|
| 前三品牌集中度 | ≤ 30%（> 40% 直接跳过） |
| Top10 销量集中度 | < 45%（> 60% 头部效应） |
| Top20 平均评论数 | ≤ 800 新手可切入 |
| 点击集中度 | < 40% 有自然空间 |
| 市场平均评分 | ≤ 4.3 有改进空间 |

## 几个值得一提的点

- **阈值不拍脑袋**：每条规则旁标注 `原文` / `已确认`，标明这个数字是框架里写的还是补的档位，并附原文引文。测试会守着「标原文的阈值必须确实写在知识库里」
- **否决线优先于总分**：前三品牌 > 40%、新品占比 < 10%、核心词 < 1 万，命中任一即判负，不靠分数蒙混过关
- **中位数意识**：均值高中位数低会被识别为「头部拉动型市场」，提醒你别用均值测算自己的销量
- **误差意识**：明确标注所有销量都是估算值，头部 ±30%、腰部以下可能超 50%
- **一套代码两种模式**：本地 `npm start` 走 Claude 流式问答；GitHub Pages 静态版在浏览器里跑评分和检索，问答退化为检索直出

## 技术栈

零 npm 依赖，只用 Node 内置模块。

- **评分引擎**：纯函数规则表，阈值集中在 `src/scorer.js` 的 `THRESHOLDS`，改口径只改一处
- **检索**：中文 BM25，分词用单字 + 二元组 + 三元组，配一张同义词表，不需要嵌入模型
- **RAG**：检索 → 组装上下文 → Claude（`claude-opus-5-5`，adaptive thinking）流式归纳，答案带引用编号
- **同构前端**：`scorer` / `retriever` / `answer` 是零 import 的纯 ESM，浏览器和 Node 跑同一份代码，本地与 Pages 结果逐字节一致
- **测试**：14 个用例，覆盖分词、检索首位命中、阈值来源一致性、四个示例市场的判定走向

## 数据是假的，逻辑是真的

示例市场（瑜伽垫、防滑洗澡椅、矫姿坐垫、宠物降温垫）的数值是编的，用来演示四种判定走向：健康、有条件、红海否决、需求不足否决。接上真实数据即可用。

## 本地运行

```bash
git clone https://github.com/Wynn-lim/amazon-market-rag.git
cd amazon-market-rag
npm start          # → http://localhost:8787
npm test           # 14 个测试
```

设置 `ANTHROPIC_API_KEY` 后启用 Claude 流式问答；不设置则自动降级为检索结果直出。
